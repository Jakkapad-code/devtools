# คู่มือเตรียมและอัดคลิป Petory

เลือกวิธีรันเพียงแบบเดียวก่อนอัดคลิป: แบบ A เปิดเว็บบนเครื่องตัวเอง หรือแบบ B เปิดเดโมใน Linux image อาจารย์ผ่าน Cloudflare ทั้งสองแบบใช้ฐานข้อมูลคนละชุดกัน

## A. รันบนเครื่องตัวเอง

ต้องมี Git, Node.js 22, Docker และเปิด Docker ไว้ ถ้า clone มาใหม่ให้เข้าโฟลเดอร์ `devtools/petory` แล้วรัน:

```bash
cp .env.example .env.local
docker compose up -d --wait
npm ci
npm run db:migrate
npm run db:seed
npm run dev
```

เปิด `http://localhost:3000` ครั้งถัดไปเปิด Docker แล้วใช้ `docker compose up -d --wait` และ `npm run dev` ก็พอ หากมี migration ใหม่ให้รัน `npm run db:migrate` ก่อนเปิดเว็บ

**ระวัง:** `cp` จะทับ `.env.local` เดิม และ `db:seed` จะลบบัญชีตัวอย่างที่ลงท้าย `@petory.local` พร้อมข้อมูลที่เกี่ยวข้องก่อนสร้างใหม่ อย่ารันซ้ำหากต้องการเก็บข้อมูลเดโมเดิม และอย่าใช้กับฐานข้อมูลจริง

## B. รันใน Linux image อาจารย์

เปิด Docker บนเครื่องที่ใช้รัน แล้วอ่านขั้นตอน clone, build และเปิด container ใน [README-INSTRUCTOR.md](README-INSTRUCTOR.md) เมื่อเข้า Linux container แล้ว:

```bash
cd /workspace/petory
until docker info >/dev/null 2>&1; do sleep 2; done
npm run demo:start
```

รอข้อความ `READY: https://...trycloudflare.com/petory/login` แล้วเปิดลิงก์นั้น เดโมเตรียม database, migration และข้อมูลตัวอย่างให้เอง ไม่ต้องรัน `npm run dev` หรือ `db:seed` แยก

Quick Tunnel เป็นลิงก์ชั่วคราว เครื่อง Docker และอินเทอร์เน็ตต้องเปิดอยู่ ใช้ข้อมูลสมมุติเท่านั้น และลิงก์อาจเปลี่ยนเมื่อเริ่มใหม่ หากมีปัญหาบน Mac ARM ดูคำสั่งสำรองในคู่มืออาจารย์

หยุดเดโมภายใน Linux container ด้วย `npm run demo:stop` แล้ว `exit` จากนั้นรัน `docker stop petory-instructor` บนเครื่องหลัก การลบ container ชั้นนอกอาจทำให้ข้อมูลเดโมหาย

## บัญชีตัวอย่าง

```text
บัญชี A: aom@petory.local
บัญชี B: niran@petory.local
รหัสผ่านทั้งสอง: petory-demo-password-2026
```

เปิดสองบัญชีในเบราว์เซอร์ปกติกับหน้าต่างไม่ระบุตัวตน เพื่อแสดงการทำงานสองฝั่ง อย่าใช้บัญชีตัวอย่างหรือรหัสผ่านนี้กับข้อมูลจริง

## ลำดับแนะนำสำหรับอัดคลิป

1. **แนะนำระบบ:** Petory ใช้ Next.js กับ PostgreSQL/PostGIS และ Docker; ถ้าใช้แบบ B ให้บอกว่า Cloudflare Quick Tunnel เป็นช่องทางสาธิตชั่วคราว
2. **Login และ My Pets:** เข้าบัญชี A เปิดสัตว์เลี้ยง เพิ่มหรือแก้ข้อมูล เลือกเพิ่มรูป JPEG, PNG หรือ WebP ได้สูงสุด 5 รูป ตั้งรูปหลักหรือลบรูป แล้วกดบันทึก
3. **Home และ Explore:** เปิดฟีด กรองหมวดหมู่หรือค้นหา สร้างโพสต์ กด Like และ Comment
4. **Follow และ Notifications:** ติดตามบัญชี B จากบัญชี A แล้วสลับไปบัญชี B เปิดไอคอนกระดิ่งเพื่อดูรายการ Follow/Comment และกดทำเครื่องหมายว่าอ่านแล้ว
5. **Matching:** เลือกสัตว์ของเราและเปิด Filters เพื่อกรองชนิดสัตว์ เพศ ขนาด บุคลิก และช่วงอายุ กด Like หรือ Pass เมื่อทั้งสองฝั่งสนใจตรงกันจึงเกิด Match
6. **กรองระยะทาง:** ในหน้า Matching กด “ยินยอมแชร์ตำแหน่ง” แล้วอนุญาตในเบราว์เซอร์ จากนั้นเลือกช่วงระยะทางใน Filters ระบบใช้ตำแหน่งโดยประมาณและแสดงระยะทางโดยประมาณเท่านั้น ผู้ใช้อื่นอาจอนุมานพื้นที่ได้ จึงควรสาธิตด้วยตำแหน่งที่ยินยอมเปิดเผย กด “หยุดแชร์ตำแหน่ง” ได้ หากอีกฝ่ายไม่แชร์ตำแหน่ง จะไม่สามารถนำมาคำนวณระยะทางได้
7. **Messages และ Unmatch:** เปิดห้องที่มีอยู่ ส่งข้อความ และดูจากอีกบัญชี หน้าแชทตรวจข้อความใหม่เป็นระยะ (*polling*) ไม่ใช่ WebSocket; ใช้ปุ่มโหลดข้อความเก่าได้ สาธิต Unmatch เป็นขั้นสุดท้าย เพราะจะปิดห้องสนทนาของคู่นั้น
8. **DevTools:** แสดง Dockerfile, Compose และ workflow GitHub Actions พร้อมอธิบายว่า Actions ตรวจโค้ดและทดสอบ ส่วนการเปิดเดโมยังสั่งเอง ไม่ใช่ CD อัตโนมัติ

## ข้อจำกัดที่ควรบอกในคลิป

- การเข้าถึงตำแหน่งต้องได้รับสิทธิ์เบราว์เซอร์และใช้งานใน secure context เช่น HTTPS หรือ localhost; ผลกรองขึ้นอยู่กับตำแหน่งที่แต่ละบัญชียินยอมแชร์ ข้อมูลเดโมเป็นข้อมูลสมมุติ
- อีเมลรีเซ็ตรหัสผ่านปิดอยู่โดยปริยาย และเดโม Quick Tunnel บังคับปิดไว้ ไม่ควรบอกว่าส่งอีเมลจริงแล้ว หากต้องการตั้ง Gmail SMTP ในสภาพแวดล้อมแยก ดู [SMTP.md](SMTP.md) และอย่าใส่รหัสผ่านลง Git หรือคลิป
- ตัวเลือก Privacy/Push ที่ระบุว่ายังไม่พร้อมไม่ใช่ฟีเจอร์ที่ใช้งานจริง
- ไฟล์ workflow ไม่ได้ยืนยันผล CI ล่าสุด ต้องเปิดแท็บ Actions ดูผลของ commit ที่ส่งจริง
- ก่อนอาจารย์ clone ต้อง commit และ push ไฟล์ที่ต้องใช้ทั้งหมดขึ้น branch ที่ส่งก่อน
